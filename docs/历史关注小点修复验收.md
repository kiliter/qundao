# 历史关注小点修复验收

日期：2026-10-22。版本：0.4.3（构建 7）。

## 问题与修正

「需要关注」的群列表曾直接使用 Alpha 的微信未读数显示小点。勾选「包含历史」后，已阅的关注记录重新可见，如果微信仍有未读，小点也会出现，造成状态矛盾。

- 关注列表按账号、群聊聚合，群小点仅统计待阅关注：待处理提醒和尚未已阅的相关摘要。
- 「包含历史」只改变可见记录范围，不改变待阅数。已阅及稍后提醒不计入；同群还有其他待阅内容时保留实际数量。
- 主窗口和刘海共用这一逻辑，页底明确小点含义。待阅判定与总待关注计数使用同一规则。
- 共用群行显式区分本地待阅与微信未读。「群聊摘要」仍从 Alpha 获取微信未读，并在数字前显示「微信」，保留同步时间和手动刷新入口。
- 不变更阅读状态或数据格式，不修改微信已读，不影响摘要任务池、白名单、模型配置及日志。

## 自动化验证

执行 `swift test --scratch-path .build`：90 项测试，87 项通过，3 项真实接口测试默认跳过，0 失败；应用编译通过。

新增 5 项回归测试覆盖：

1. Alpha 未读为 5 时，历史记录全部已阅仍不亮点。
2. 同群历史与新待阅混合时，只计待阅；反复切换历史开关不改变数量，群计数合计与总待关注数一致。
3. 账号隔离、重复记录去重、稍后提醒不计入，提醒到期恢复待关注后重新计入。
4. 一键已阅后各群清点，实际文件持久化及重新加载后仍正确；新相关摘要到达只恢复对应群的小点。
5. 单条已阅只减少对应群数量，不影响同群其他待阅内容及其他群。

现有摘要调度、分页快照、失败重试、上下文分段、阅读状态和日志测试全部通过。
