# REST 与全流程白名单验收

验收日期：2026-10-22。安装版本：群岛 0.5.0，构建号 8。

## 本轮规则

用户最终确认：即时和周期都只处理白名单群。本规则覆盖此前“周期扫描所有群”的设计。

- 私聊、白名单外群聊和非当前账号的推送在入口丢弃，不进入去重状态、消息缓存、缓冲池、决策批次或模型，也不记录聊天原文。
- 白名单群进入容量或固定时限触发的缓冲池，经本地规则或 Jev 判断，相关才提交即时摘要。保留 @我、@所有人、@all 等识别。
- 周期扫描、手动生成、断线补查和恢复任务均限白名单。群列表元数据仍用于添加群聊及展示未读数，不代表读取这些群的原文。
- 两种触发继续共用摘要池：同群合并、不同群有限并发，执行时读取全部未读快照；成功标记与结果一起持久化，相同未读范围不重复调用模型。
- 移出白名单时清理当前账号该群的处理缓存、缓冲、决策批次、补查进度与即时/周期任务，并取消在途工作。网络返回、后续分段调用和落盘前再次检查资格，丢弃越界迟到结果。
- 已经发出的网络请求无法撤回。升级前已完成的历史摘要和日志保留，不自动删除；保留的历史内容不会作为新待办重放。

## Alpha HTTP 接口

固定服务地址为 `http://127.0.0.1:9527`，鉴权使用 `Authorization: Bearer <令牌>` 请求头。源码不再调用 `/mcp` 或 `tools/call`。

| 用途 | 方法与路径 | 参数及响应约定 |
| --- | --- | --- |
| 账号列表 | `GET /api/v1/accounts` | 读取 `accounts`，校验有效状态 |
| 群列表与未读数 | `GET /api/v1/sessions` | 查询 `account`、`limit=200`、`offset`；读取 `items`，只保留群聊元数据 |
| 消息分页 | `GET /api/v1/messages` | 查询 `account`、`username`、`limit`、`offset`、`order`，可选 `start` / `end`；读取 `messages`、`sender_name` 和 `nextOffset` |
| 实时推送 | `POST /api/v1/push/messages` | 请求体包含 `accountId`，响应为 SSE；推送正文解析前检查群和白名单 |

REST 的 `start` / `end` 为包含边界的 Unix 秒，内部调用仍使用毫秒：扩大到整秒查询，再按毫秒过滤，避免同一秒内漏读。内部 `rest-v1:` 游标绑定账号、群、时间范围及排序；校验响应身份和 offset 推进，错误时保留任务等待重试。消息服务器 ID 保持字符串精度。

旧 MCP 补查游标不能直接用于 REST，因此以 `alphaRESTVersion=1` 进行一次性迁移。迁移清空补查游标，保留去重标识和成功摘要标记。HTTP 错误仅输出状态码与路由，不记录原始错误正文。CPA 与 Jev 已有的直接 HTTP 调用、自定义 OpenRouter Base URL 和日志 UI 保留。

## 尚未验证的行为

- 本轮未主动发送测试微信消息，未重新调用真实 CPA 检查摘要质量。已观察到一次真实消息到 Jev 的成功判断，但未用人工标注样本验收准确率；白名单外消息拒绝、命中后摘要及故障行为由自动化测试覆盖。
- Alpha REST 没有原子未读快照及独立已读边界接口。当前以“最新 N 条对应 N 条未读”为基础，分页前后校验末条与数量，变化时重取；持续高流量、边读边收及长时间休眠恢复仍需真实运行观察。
- REST 与原 MCP 的未读数据来自 Alpha。改用 REST 不代表微信客户端到 Alpha 的已读同步延迟或不一致已经解决。
- 历史摘要和历史诊断日志中的既有内容未删除；“入口不落盘”约束升级后的消息处理。诊断日志继续明确提示包含聊天原文，排除密钥和鉴权头。
