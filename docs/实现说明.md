# 实现说明

## 结构

- `QundaoCore`：消息/状态模型、Alpha 客户端、CPA 客户端、目录解析、规则、推送解析和队列；不依赖界面。
- `Qundao/Stores`：应用状态、磁盘存储、监听与调度。
- `Qundao/Services`：钥匙串、本地语义筛选、日志、刘海窗口。
- `Qundao/Views`：主窗口、消息详情、摘要、配置和日志。
- `prototype`：已确认的 HTML 高保真原型。

## 任务生命周期

`MessageAdmission` 先校验当前账号、群聊标识与显式白名单。推送解析在提取正文前过滤，私聊及白名单外群聊直接返回，不缓存、不入池、不调用模型、不记录原文。通过校验后才去重并进入 `RealtimeBuffer`，按账号和群分组。容量触发清理当前账号的缓冲，定时触发按每群首条到达时间计算；后来的消息不能推迟截止时间。缓冲先转为可恢复的摘要任务或 Jev 批次，再移除，避免中途退出遗漏尚未处理的群。

`SummaryCoordinator` 共用一份 `SummaryState`，任务键由账号和群生成。即时/周期只作为来源集合，等待时合并，运行中只设置一次后续检查。默认最多 3 群并发（可设置 1–8），同群只占一个执行槽；即时来源优先于等待周期来源。失败保留所有来源和触发信息，10 秒起步退避至 300 秒。停止或重启时运行任务恢复为等待，账号之间独立。

`PeriodicSummaryClock` 与消息同步独立。周期扫描只处理 Alpha 所选账号的白名单群，无未读跳过；有未读时取得当前末条，与 `SummaryState.markers` 比较。相同不入队；变化或没有成功记录才入队。单群头部读取失败入队重试，不能把本地入库或 `analyzed` 当作摘要成功。

`UnreadSnapshotLoader` 在执行时重新从 Alpha 获取完整未读：以未读数量 N 和末条 ID 固定范围，采用末条毫秒时间 + 1 的排他上界，按降序游标读满 N 条后反转。每页去重并验证账号、群、时间上界、游标推进和消息数量；分页前后复核末条和未读数量。边界变化时重取，最多 3 次后交由任务池退避。Alpha 没有原子未读或已读边界接口，因此当前实现依赖“最新 N 条对应 N 条未读”的服务语义，不能宣称原子快照。

`SnapshotSummarizer` 使用实际序列化输入计算预算。完整快照可容纳时一次请求；否则完整拆分消息，超长单条按字符拆分，分段结果再逐层汇总。中间结果超长也完整分片，禁止静默截断；汇总最多 12 层，不收敛则整次失败。模型每步都校验非空摘要、相关性与证据 ID。每份输入的阶段和原文、实际响应、HTTP 错误均进入既有诊断日志。

模型成功后，`AppStore.persistSummary` 形成包含结果、完整证据、成功末条和任务状态的新状态副本。`SnapshotPersistence` 将临时文件以 600 权限写全并同步后，原子重命名替换状态文件；成功后才替换内存快照并通知。保存失败不能推进成功标记。标记只取实际输入快照末条，不读取请求结束时的最新消息。

旧版状态保留摘要、UI、白名单和连接配置。旧消息候选迁移为新任务，旧 Jev 待判断消息迁移为持久化批次；旧 `analyzed`、同步进度和旧部分摘要不生成成功标记。0.5.0 启动恢复、切换账号和修改白名单时清理当前账号范围外的处理缓存与待办，并取消移出群的在途任务。每次网络返回、模型分段调用与保存结果前再次校验白名单。既有历史摘要和日志不自动删除，也不作为待处理消息重放。

## Alpha REST

`AlphaClient` 直接使用 HTTP REST：账号 `/api/v1/accounts`、会话 `/api/v1/sessions`、消息 `/api/v1/messages`；实时消息使用 `POST /api/v1/push/messages` 的 SSE。所有请求通过 Bearer 请求头鉴权，不在 URL 中携带令牌，不使用 MCP。

会话和消息查询通过 `account` 明确账号，消息查询使用 `username` 指定群。REST 时间边界为包含边界的 Unix 秒，因此先扩大到整秒读取，再按毫秒范围过滤；整页被过滤但仍有下一页时继续读取。offset 分页封装为绑定账号、群、排序与时间范围的内部游标，校验每页身份、完整性及偏移推进。旧 MCP 补查游标一次性清空，成功摘要标记和消息 ID 去重仍保留。

群列表元数据用于添加白名单和显示未读状态；完整消息只读取白名单群。Alpha 错误仅记录路由和状态码，不将服务端原始错误正文写入日志。具体参数及验证结果见 [REST 与全流程白名单验收](REST与全流程白名单验收.md)。

## 原生刘海

主窗口使用 SwiftUI；刘海仅用 `NSPanel` 处理非激活窗口、跨桌面显示和屏幕几何定位，内部仍是 SwiftUI。

从 `NSScreen` 的安全区和刘海两侧可用区域计算展开位置；外接屏或无刘海屏幕顶部居中显示。悬停展开，点击固定，移出延迟收起。连接、分析、摘要和提醒由同一应用状态驱动。

## 安全与状态

不保存接口令牌到项目文件，运行事件不记录真实消息正文；按用户要求新增的诊断日志会保留入参、出参及聊天原文，界面明确说明。首次启动不自动导入 Codex 密钥，不自动开始监听；用户在界面保存连接并开始后才处理真实消息。模型没有发送微信消息的工具，聊天文本被明确视为不可信数据。

保留本地失败进度；状态文件不能读取时停止写入，避免覆盖原文件。

## 0.2 增量

- `ConversationBrowser` 统一摘要与待关注群聊列表，`ChatTranscript` 统一群摘要原文与提醒详情；选择状态与滚动区域独立。
- 原文按账号、群、消息键去重，优先使用已同步缓存，缓存缺失时保留摘要证据，避免点击原文后出现空白。
- 白名单使用显式添加，旧选择只备份、不自动沿用。0.2 仅约束即时候选；0.5.0 已按最新要求改为同时约束即时、周期和手动摘要，移出群即撤销两种来源的待处理任务。
- `JevClient` 支持自定义 Base URL、OpenRouter Decisions 和 TypeSafe System One，使用 `noul` 问题，严格校验逐消息的两个概率。`JevMonitor` 独立单并发队列，待判断集合落盘，故障使用本地识别兜底并退避重试。
- 全员提及支持中文、英文、全角 @ 和结构化 `notify@all`；排除自身发言、邮箱及相似英文用户名。
- 刘海以 AppKit 窗口尺寸动画为主，内容延迟淡入，悬停有短延迟与收起防抖；固定阅读时提醒不会抢走所选页。

## 0.3 日志与连接

- `JevConfiguration` 统一解析 Base URL、协议和模型，支持 OpenRouter 标准地址、完整端点及自定义代理。连接配置使用界面草稿，保存后整体应用；切换时取消旧决策任务，旧服务结果不会落地。
- `DiagnosticLogStore` 按日和文件大小归档，JSONL 文件权限 600。每次追加同步到磁盘，文件名在归档后保持不变。读取使用倒序块扫描及文件偏移游标，历史页不受新记录追加影响，跨 64 KB 的中文大记录与不完整尾行均有回归测试。
- 本地日志包含输入消息、身份配置、规则/语义结果及后续动作；Jev、CPA 在请求开始和成功/失败时记录同一关联编号、请求体、响应体、HTTP 状态及耗时，失败保留原始响应便于诊断。鉴权头不进入记录，密钥值和敏感鉴权字段脱敏。
- 日志 UI 使用完整双栏可视区，后台读取、来源过滤、入参/出参/错误页签、复制、每页数量切换及前后分页。0.4.2 起由成功落盘后的 `AsyncStream` 事件驱动刷新，批量通知只缓冲最新版本；选择旧记录只暂停跟随，最新页仍更新并保留详情，历史分页收到新日志提示。
- 0.4.2 起刘海直接显示统一「需要关注」，与主窗口复用 `AttentionBrowser`、`ConversationBrowser` 和 `SummaryReadingCard`，不再区分找我的消息与相关摘要。

## 0.4.2 统一阅读

- `SummaryReadingCard` 是群聊摘要、需要关注和刘海共用的卡片；正文固定显示摘要，原文使用共享弹窗与 `ChatTranscript`。模型摘要未完成的直接提醒使用识别出的简述，原消息仍可打开。
- 逐条、本群、页面一键已阅均通过候选快照原子保存后更新界面。操作范围固定为当前账号、点击时指定的记录 ID，不修改 Alpha 未读或成功摘要标记，不提前标记后续新到的摘要。
- `SummaryTimeline` 以 Alpha `last_activity_unix_ms` 排序有未读的群，其余按摘要证据中最新消息时间排序。分批摘要也按消息时间排序；只有无证据的旧记录回退使用生成时间。

验证范围见 `摘要流程验收.md`；模拟模型测试与真实接口验收分别列出。
