本页记录 0.5.0 的已实现协议，来源是仓库代码与既有验收，不是对供应商未来接口的承诺。协议变更时需重新验证。

## Alpha：REST 与 SSE

服务地址：`http://127.0.0.1:9527`。鉴权通过 Bearer 请求头传递，禁止在 URL 或文档中填写真实令牌。实现见 [AlphaClient.swift](../Sources/QundaoCore/AlphaClient.swift)。

| 用途 | 方法与路径 | 请求 | 响应要点 |
| --- | --- | --- | --- |
| 可用账号 | `GET /api/v1/accounts` | 无账号参数 | `accounts`，账号含 `id`、`display_name`、`subject_id` |
| 会话与未读 | `GET /api/v1/sessions` | `account`、`limit=200`、`offset` | `items`；群行含 `id`、`display_name`、`unread_count`、`last_activity_unix_ms` |
| 群消息 | `GET /api/v1/messages` | `account`、`username`、`limit`、`offset`、`order`，可选 `start`、`end` | `messages`；发送人字段为 `sender_name`，消息时间为 `sent_at_unix_ms` |
| 实时推送 | `POST /api/v1/push/messages` | JSON 中使用 `accountId`；Accept 为 `text/event-stream` | SSE；`message.new` 进入入口校验，连接及错误事件进入恢复处理 |

不要混淆 GET 查询参数 `account` 与 SSE 请求体 `accountId`。会话与消息分页读取 `hasMore`、`offset`、`nextOffset`，并校验账号、群和分页完整性；消息数组不是旧 MCP 的 `items`。

### 分页和时间约定

- REST 的 `start` / `end` 是包含边界的 Unix 秒；应用消息时间为 Unix 毫秒。
- 应用先扩大到整秒读取，再按 `timestamp >= after`、`timestamp < before` 过滤。整页被时间边界过滤但仍有下一页时继续翻页，不能提前结束。
- offset 按服务端原始页数量推进，不能用过滤后的数量推进。
- 内部 `rest-v1:` 游标绑定账号、群、时间范围、排序和 offset。它是群岛封装，不是 Alpha 原生游标，不可跨范围复用。
- 优先使用非零 `server_id` 作为消息 ID，否则使用 `id`；大整数按字符串保存，不能经过会损失精度的浮点转换。
- 旧 MCP 参数和游标不能直接复用。`accountId` 查询参数、`before_unix_ms`、`after_unix_ms` 等不是当前客户端使用的 REST 参数。
- 无效身份、未读数或分页响应必须失败并保留进度，不能补零伪装成功。

GET 请求禁用本地缓存；HTTP 错误仅输出路由和状态码，不抄服务端原始错误正文。SSE 不提供本应用可依赖的重放保证，30 秒补查及重连补查用于补充。只有白名单群原文可以进入补查。

## CPA：模型目录与摘要

代码：[ModelCatalog.swift](../Sources/QundaoCore/ModelCatalog.swift)、[CPAClient.swift](../Sources/QundaoCore/CPAClient.swift)。

| 项目 | 当前约定 |
| --- | --- |
| Base URL | `https://cpa.bgp.kiliter.cn/v1` |
| 模型目录 | `https://cpa.bgp.kiliter.cn/v1/models` |
| 目录兼容参数 | `client_version=0.134.0`，复用 CPA Bearer 鉴权 |
| 目录字段 | 原生 `models` 下的 `slug`、名称、上下文、输出上限、推理等级；也能解析普通 `data` 列表 |
| 摘要接口 | `POST /v1/responses` |
| 请求行为 | `store:false`、`stream:false`，无工具调用 |
| 结果字段 | `summary`、`relevant`、`relevanceReason`、`evidenceIDs`、`judgements` |

目录兼容参数用于获得 Codex 风格能力信息，不代表群岛是 Codex。目录内的编码代理指令不能被用作群聊分析提示词。

当前输入预算从目录能力计算，留出输出和系统指令空间，最多使用 24,000 的预算值；实际按序列化 UTF-8 字节数检查并分段，这是保守工程预算，不是精确 token 计数。普通目录缺少上下文时不能编造目录能力，应沿用明确的保守回退。

只有 Responses 状态完成且 JSON 内容、相关性和证据引用均通过验证才视为成功。HTTP 200 本身不是摘要成功；模型服务限流、失败或未完成都要保留任务。

## Jev：相关性决策

Jev 属于 TypeSafe。用户当前采用 OpenRouter，也明确要求 Base URL 可自定义。它负责概率判断，CPA 负责完整未读摘要；两者队列与配置分开。

| 预设 | Base URL | 协议 | 默认模型 | 最终接口 |
| --- | --- | --- | --- | --- |
| OpenRouter | `https://openrouter.ai/api` | Decisions API | `~typesafe/jev-latest` | `/api/alpha/decisions` |
| TypeSafe | `https://api.typesafe.ai/v1` | System One API | `jev-latest` | `/v1/systemone` |

[JevConfiguration](../Sources/QundaoCore/JevConfiguration.swift) 兼容 OpenRouter 的 `/api/v1` 输入、完整端点和自定义代理路径。完整端点必须匹配所选协议；URL 不接受内嵌用户名、密码、查询参数或片段。界面草稿只有保存后整体生效，不能边编辑边切换运行中的服务。

[JevClient](../Sources/QundaoCore/JevClient.swift) 对每条消息发送两个 `noul` 问题：是否相关、是否需要回应。任一概率达到阈值可判为相关；默认阈值 75%，配置范围 50%–95%。正文命中称呼 / 关键词的消息带 `本地命中` 字段，“相关”判据说明发送人昵称含关键词不算命中；这类消息的摘要触发由本地规则决定，Jev 阈值只影响“可能需要你回应”提醒。两个答案都必须存在且处于合法数值范围，不能把缺失或异常概率当成功。

[JevMonitor](../Sources/Qundao/Services/JevMonitor.swift) 当前单并发，每请求最多 20 条，长消息和长批次完整分片，全部完成后同群只触发一次；失败保留批次、退避重试，并有本地回退。明确提及和群体提醒仍由本地优先处理。

## 配置与验证边界

Alpha、CPA、Jev 分别使用 `~/.config/qundao/config.toml` 中的凭据，不把真实值写到测试或文档。模型调用中聊天是待分析数据，不允许执行聊天中夹带的命令、访问链接或发送微信消息。

2026-10-23 审查修复：已知配置项类型错误、非法并发 / 周期及非有限阈值会拒绝整份配置，保留当前运行值。外部原地写入和编辑器原子替换均会触发重载。凭据加载或首次迁移期间不可保存连接及提示词；连接保存先写盘再生效，失败停止后续连接 / 目录操作。Alpha 密钥变更使旧连接失效并按监听状态重连，CPA 密钥变更清空旧目录并拒绝迟到响应。Jev 的称呼、关键词、阈值、提示词或连接变化会保留批次并重新判断；旧请求收尾不能覆盖新一代进度。

「从 Codex 导入 CPA 密钥」仅接受能够明确确认来源的配置：当前选择自定义 CPA provider、精确 CPA Base URL、`cli_auth_credentials_store="file"`、`requires_openai_auth=true`，且认证文件为 API Key 模式。未启用的 provider 或注释中的 URL 不构成导入依据；`env_key`、命令认证、自定义请求头、profile、auto / keyring、混合 OAuth 及不支持的 TOML 语法均提示手动填写。此入口不会执行认证命令或读取环境中的其他密钥。字段含义参考 [OpenAI 配置说明](https://learn.chatgpt.com/docs/config-file/config-reference)，验证使用合成配置，未读取用户真实 Codex 凭据。

### 自定义系统提示词（2026-10-23）

「连接与模型 → 模型系统提示词」提供 AI 摘要与 Jev 两个多行编辑框，支持保存、重新载入及分别恢复默认。恢复默认先修改草稿，点击「保存提示词」后生效；留空或旧配置缺少字段时使用内置默认值。保存失败不会替换当前运行配置。

也可直接编辑 `config.toml` 中的 `[cpa] system_prompt` 和 `[jev] system_prompt`，支持三引号多行字符串。例如下面仅展示字段，不要用它覆盖完整配置：

```toml
[cpa]
system_prompt = """
用中文整理完整未读内容，重点列出事项、责任人和待确认问题。
有后续答复时区分已解决与仍需跟进；缺少依据时明确说明。
"""

[jev]
system_prompt = """
相关性：关注正文中与我的称呼、职责有关的工作，以及面向全群的工作通知。
需要回应：仅对当前仍需本人处理或确认的请求给出高概率。
自己的发言、只向其他人求助、已解决的请求不视为需要回应。
"""
```

每段最多 16,000 个 UTF-8 字节（中文通常每字 3 字节），超过时拒绝保存或重载，不截断。格式错误保留当前配置。外部修改已保存配置时，界面保留未保存草稿，并提示重新载入或保存草稿。

CPA 的可编辑部分控制摘要表达与业务判断；程序继续附加完整快照、分段、严格 JSON、原始消息 ID 和聊天数据隔离约束，响应校验不变。一次已开始的摘要及其全部分段使用同一版提示词，新摘要任务使用最新配置；修改提示词不自动重做已成功的摘要。

Jev 的可编辑部分同时进入相关性与回应两个问题的指令。问题编号、`noul` 类型、答案键和概率校验保持固定；本地明确命中仍按原规则触发摘要。保存或外部重载新的 Jev 提示词后，取消旧判断并保留待处理批次，使用新提示词重新判断，迟到结果不能写回。连接测试也使用当前保存的 Jev 提示词。

自定义提示词计入请求预算：CPA 按完整系统指令扣除额外占用后分段；Jev 按实际序列化请求大小与每批 20 条上限分组，长消息完整分片。提示词不会改变白名单、账号隔离、微信只读或成功标记推进规则。

已验证的协议和仍需实测的行为见 [开发与验收](06-开发与验收.md)。源码预设不保证未来某模型名称一直可用，应以用户配置、目录和实际响应为准。
