## 项目结构

项目以 [Package.swift](../Package.swift) 为入口，Swift tools 5.10，最低 macOS 14。`Qundao` 为 GUI 可执行产品，依赖不含 UI 的 `QundaoCore`，测试目标为 `QundaoCoreTests`。

| 路径 | 责任与常用入口 |
| --- | --- |
| [Sources/QundaoCore](../Sources/QundaoCore) | 领域模型、REST、规则、缓冲、统一摘要池、快照、分段及持久化 |
| [Sources/Qundao/Stores](../Sources/Qundao/Stores) | `AppStore` 状态协调、监听和扫描；`DiskStore` 本地目录入口 |
| [Sources/Qundao/Services](../Sources/Qundao/Services) | Jev 监听、本地语义、日志、配置文件监视、旧钥匙串迁移、刘海 AppKit 面板 |
| [Sources/Qundao/Views](../Sources/Qundao/Views) | 主窗口和共享阅读、配置、日志组件 |
| [Sources/Qundao/App](../Sources/Qundao/App) | 应用、菜单栏、激活和唤醒处理 |

已有 `AnalysisQueue.swift` 等兼容代码不代表新的生产摘要入口；当前统一摘要调度在 `SummaryCoordinator`，不要建立第二套摘要任务池。

## 本地构建与运行

在仓库根目录执行：

```bash
swift test --scratch-path .build
./script/build_and_run.sh --build-only
./script/build_and_run.sh --verify
```

安装包默认以 Release（`-c release`）构建；Debug 未开启优化，SwiftUI 页面切换明显更慢，只在 `--debug` 调试时使用。macOS `Slider` 不要设置细粒度 `step`，会为每个步进绘制刻度，曾让“刘海与通知”切换卡顿数秒；需要取整时在 Binding 的 set 中处理。

`--build-only` 生成并签名 `dist/群岛.app`；`--verify` 会停止正在运行的群岛，构建、安装到 `/Applications/群岛.app`、启动并检查进程。不要为文档修改重启用户应用，也不要用裸 SwiftPM 可执行文件替代 GUI 应用包验收。

脚本复用固定开发签名身份，新机器通过 `QUNDAO_SIGNING_IDENTITY` 指定已有证书。不要自动创建证书、使用变化的临时签名或修改系统信任；钥匙串授权由用户在系统提示中完成。

## 真实接口验证

[LiveTests.swift](../Tests/QundaoCoreTests/LiveTests.swift) 默认跳过没有环境配置的真实测试：

| 环境变量 | 用途 |
| --- | --- |
| `QUNDAO_TEST_ALPHA_TOKEN` | Alpha 只读账号、群与未读快照验证 |
| `QUNDAO_TEST_ALPHA_GROUPS` | 逗号分隔的实际白名单群标识，限制完整原文分页测试范围 |
| `QUNDAO_TEST_CPA_KEY` | 真实 CPA 目录与合成消息摘要测试 |

变量由调用环境安全注入，不把值写入命令示例、脚本、仓库或输出。当前 Alpha 快照测试使用首个可用账号，并在给定群集合内选择 2–50 条未读的群；多账号环境需核对范围，条件不满足可能跳过，不能误报为验证通过。

真实调用不会发送微信消息或修改微信已读。为了测试不应擅自改真实白名单或批量已阅。Jev 的协议测试主要使用模拟 HTTP，不能把其通过当作实际模型准确率验收。

## 性能基准

`PerfProbe` 用 os_signpost（Instruments「Points of Interest」）标记页面切换与刘海动画，并写 `cn.kiliter.qundao` / `perf` 日志（只含页面名、毫秒数和帧统计）。用环境变量启动内置基准，只切换导航和展开 / 收起刘海，不改数据：

```bash
QUNDAO_PERF_BENCH=1 /Applications/群岛.app/Contents/MacOS/Qundao      # 3 轮页面切换 + 5 次刘海
QUNDAO_PERF_BENCH=notch /Applications/群岛.app/Contents/MacOS/Qundao  # 只测刘海
open -n --env QUNDAO_PERF_BENCH=live /Applications/群岛.app             # 不驱动界面，统计每次真实滚动（含惯性）的帧
QUNDAO_PERF_BENCH=trackpad …                                            # 向本进程投递带手势 / 惯性阶段的滚轮事件
/usr/bin/log show --last 2m --style compact --predicate 'subsystem == "cn.kiliter.qundao" AND category == "perf"'
```

注意：xctrace 的 Animation Hitches / Time Profiler 会在系统临时目录写入很大的 `instruments*.ktrace`（30 秒可达 20 GB），不受 `TMPDIR` 影响；录制要短，录完立即删除。合成滚轮事件不移动真实光标、不触发窗口级几何与跟踪区域更新，测得满帧不代表触控板体验，滚动类问题需要人工滑动配合采样。自动化工具经辅助功能读取界面时，主线程会长时间做 AX 遍历，测出的“卡顿”不代表用户体验，应优先用内置基准驱动。

2026-10-22 优化前后（Release，同一台 120 Hz 机器，真实数据规模约 60 群、400 条缓存消息、57 批摘要）：

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 空闲 20 秒 Animation Hitches | 487 次 | 17 次 |
| 无变化时保存一次快照（合成基准） | 1.63 ms | <0.01 ms |
| 检查点变化时保存一次（合成基准） | 1.96 ms | 0.17 ms |
| 页面首次进入 | 238–298 ms，伴随约 290 ms 主线程卡顿 | 21–58 ms（启动后预建） |
| 页面再次进入 | 每次重建，同首次 | 18–56 ms |
| 刘海展开 / 收起 | 动画期间每秒约 40 次掉帧 | 每次约 57 帧，超时帧 0–1，最长 16.7 ms |
| 拖动窗口宽度（120 帧，主线程帧间隔中位数） | 保留页面初版（全部页面用约束跟随窗口重排）：45–87 ms | 只排可见页面：14–24 ms |
| 偏好设置页真实触控板滚动（35 秒人工采样） | 单段超时帧 33–47，主线程几乎满载；隐藏的日志页、弹出菜单、侧边栏每帧随之更新 | 单段超时帧 0–2，主线程 SwiftUI 排版采样 6233 → 857 |
| 页面切换（隐藏页卸下后重新挂回） | 18–56 ms（隐藏页常驻窗口） | 30–82 ms；以此换取滚动时隐藏页不参与排版 |
| 空闲 8 秒主线程采样（刘海空闲） | 1042 次（10 Hz 时钟持续重算工具栏） | 60 次 |
| 正常运行 10 分钟（监听中） | — | CPU 空闲 0–1%，偶发 9–11%；内存约 210 MB 稳定 |

`QUNDAO_PERF_BENCH=resize` 为窗口缩放基准。未验证：更长时间（数小时）运行、外接显示器 / 无刘海屏幕、减少动态效果开关下的视觉效果（代码路径改为无动画直接设置形状与透明度，未在开启该系统选项时实测）。

## 历史验证基线

### 2026-10-22 主窗口 P5 原生化

- 根据用户确认的 `prototype/主窗口P5风.html` 改造七页主窗口及共享阅读组件。保留业务 Store、消息处理链路、页面宿主缓存、设置页 AppKit 滚动及无细粒度刻度的滑杆。
- `swift test --scratch-path .build`：共 125 项，121 项通过、4 项跳过、0 失败（核心 122 项含 4 项跳过；刘海布局与合成渲染 3 项通过）。没有使用真实聊天作为测试夹具。
- 通过 `script/build_and_run.sh --verify` 进行 Release 构建、固定身份签名、安装到 `/Applications/群岛.app` 并启动。
- 实际打开七页核对样式、字段与滚动；验证历史关注不恢复计数、原文弹窗与 Esc 关闭、群列表上下键导航、⌘ 数字切页、长设置页底部可达。使用系统窗口布局检查最小内容区域 940 × 620 pt，摘要正文及操作未裁切，连接表单自动切换单列。
- 自动化读取表格时曾超时；后续正常读回，进程采样时主线程处于事件等待，不能据此认定应用持续卡顿，也不把这次采样当作完整性能基准。
- 没有为了 UI 验收执行真实群添加 / 移出、批量已阅、模型连接测试或更改密钥与通知配置；这些操作的端到端验证不在本次已验收范围。新增关注横幅的真实触发、系统减少动态效果、多显示器和长时间性能仍需单独验收。
