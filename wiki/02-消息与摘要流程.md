# 消息与摘要流程

[返回 Wiki 首页](README.md)

## 已确认的不变量

即时判断和周期扫描只是两种触发方式，共用一个摘要流程。触发决定“要不要检查这个群”，执行阶段再读取“这个群当时的全部未读”。去重只避免相同未读范围重复调用模型，不从下一次输入中删除已摘要的旧未读。

入口和流程对应代码：[MessageAdmission](../Sources/QundaoCore/MessageAdmission.swift)、[AppStore](../Sources/Qundao/Stores/AppStore.swift)、[SummaryCoordinator](../Sources/QundaoCore/SummaryScheduler.swift)。

## 即时链路

1. Alpha SSE 推送到达，先验证当前账号、群标识及白名单。拒绝的数据不进入正文缓存、去重集合、缓冲池或原文日志。
2. 允许的消息按账号、群、消息 ID 去重，写入可恢复缓冲。
3. 当前账号缓冲达到容量，或某群首条入池消息等待到期时 flush。后续消息不能重置该群截止时间。
4. 每群单独做本地规则或 Jev 判断；无关不提交即时摘要，同批同群多条命中只提交一次。
5. 明确提及和群体提醒由本地规则优先处理；开启直接提醒时可先生成关注记录，随后安排完整未读摘要。

当前默认容量为 30 条，固定等待 3 秒；配置范围分别为 1–500 条、0.5–30 秒。容量判断针对当前账号缓冲总量，时间判断按群首条到达时间。

本地模式中，称呼、关键词或系统语义候选可以触发摘要，由摘要模型结合完整上下文判断实际相关性。Jev 模式中，非明确本地命中的批次交给 Jev；无密钥或调用失败时已有本地回退路径。自身发言不触发“有人找我”的判断。

代码：[RealtimeBuffer.swift](../Sources/QundaoCore/RealtimeBuffer.swift)、[RuleEngine.swift](../Sources/QundaoCore/RuleEngine.swift)、[JevMonitor.swift](../Sources/Qundao/Services/JevMonitor.swift)。

## 周期与手动扫描

周期时钟独立于消息到达，开始监听后经过完整周期再触发；当前 UI 提供 5 / 15 / 30 分钟，默认 15 分钟。「生成未读摘要」主动启动相同扫描。

扫描仅处理当前账号的白名单群。无未读直接跳过；有未读时获取当前末条，与 `SummaryState.markers` 中同账号、同群的上次成功末条比较。相同则跳过，变化或没有记录则入队。读取失败保留重试机会，不能当作没有新消息。

## 统一任务池

| 状态或事件 | 行为 |
| --- | --- |
| 同群尚无任务 | 创建任务，保存触发来源 |
| 同群任务等待中再次触发 | 合并来源，执行时读取最新快照 |
| 同群运行中再次触发 | 标记一次 `needsCheck`，不启动并行同群请求 |
| 不同群等待执行 | 默认并发 3，上限可设 1–8；即时来源优先 |
| 执行期间只有无关新消息 | 不单独制造新的即时任务 |
| 成功且有待检查触发 | 重新读取快照，末条有新增才再次调用模型 |
| 失败或保存失败 | 不推进标记，保留任务及新触发，从 10 秒退避至最多 300 秒 |
| 停止或重启 | 运行状态恢复为待执行，成功标记保留 |
| 移出白名单 | 清理处理缓存与两类待办，取消在途任务，拒绝迟到结果 |

即时任务不会强行打断已运行的周期请求。任务键采用账号与群组合，不能只用群 ID。

## 获取完整快照

当前 [UnreadSnapshotLoader](../Sources/QundaoCore/UnreadSnapshot.swift) 从 Alpha 读取未读数量 N 与最新消息，固定末条时间上界，再按降序分页读取 N 条并反转为原顺序。每页验证身份、边界、去重和游标推进；前后复核末条与数量。

读取期间边界变化会重新读取，最多 3 次后交任务池退避。消息缺失、分页停滞或返回越界都不能提交部分成功。Alpha 目前没有原子未读快照和独立已读边界，当前实现依赖“最新 N 条对应 N 条未读”的语义，限制见 [排查页](08-已知限制与排查.md)。

## 上下文预算与提交

[SnapshotSummarizer](../Sources/QundaoCore/SnapshotSummarizer.swift) 按实际序列化输入大小切分。完整快照能容纳则一次请求；否则先整理所有片段再逐层汇总，超长单条按字符拆分，保留原消息 ID。超长中间结果也完整拆分，最多 12 层，不收敛则失败。

每个结果必须有非空摘要、合法相关性和有效证据引用；相关结果必须提供证据。不允许引用未输入的消息，也不允许“无关但需要回应”的矛盾结果。

结果、原文证据、快照成功末条及任务状态一起原子保存。标记来自本次实际快照，绝不在请求完成时取群里最新消息替代。

## M100 / M101 验收例

| 时刻 | 微信未读范围 | 行为 |
| --- | --- | --- |
| 首次即时命中 | M1–M100 | 对全部 100 条摘要，成功后记录 M100 |
| 周期检查 | 仍为 M1–M100 | 末条相同，不调用摘要模型 |
| M101 到达但即时判断无关 | M1–M101 | 不因到达自动摘要，等待下一次合法触发 |
| 后续相关命中或周期扫描 | M1–M101 | 若旧消息仍未读，对全部 101 条摘要 |
| M102 在上一请求运行中到达 | 本次快照仍止于 M101 | 本次成功只记录 M101；M102 是否继续摘要取决于新的合法触发 |

自动化验收映射见 [开发与验收](06-开发与验收.md)。
