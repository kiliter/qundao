# 决策记录

[返回 Wiki 首页](README.md)

本页按聊天中决定的先后关系整理，统一于 2026-10-22 归档。除明确注明的日期外，编号不代表各项决定的精确发生日期。后来的明确要求覆盖早期设计，不能从旧验收或原型恢复已废弃规则。

## D01：产品聚焦办公关注

**状态：生效。** 群岛用于在大量微信群中减少漏看与自己相关的办公事项。保留主窗口、菜单栏和参考 Vibe Island 的刘海交互；最初先确认 HTML 高保真，再开发原生版本。

影响：不向自动聊天、自动回复或全量聊天管理扩展；刘海应帮助用户快速阅读需要关注的内容。

## D02：统一需要关注入口

**状态：生效，覆盖早期分类。** 用户认为“找我的消息”和“相关摘要”都需要看，不需要两类入口。内部可保留规则、Jev、摘要判断等来源，界面统一为「需要关注」。

影响：主窗口、菜单栏和刘海共用关注流及待阅计数；无关摘要不进入刘海。依据见 [AttentionFeed](../Sources/QundaoCore/AttentionFeed.swift)。

## D03：摘要固定使用全部未读

**状态：生效，覆盖仅摘要增量的做法。** 即时消息和周期扫描只产生触发，摘要执行时必须重新获取该群全部未读，包括以前已经摘要但仍未读的消息。

去重依据为成功处理的快照末条，不能用消息已入库代替。M100 成功后末条仍为 M100 就跳过；新增 M101 后若原消息仍未读，下次输入为全部 101 条。两种触发共用任务池，失败不推进标记。

完整流程见 [消息与摘要流程](02-消息与摘要流程.md)。

## D04：所有处理都受白名单约束

**状态：生效，覆盖“周期扫描所有群”。** 最终确认原话：即时和周期都只处理白名单群。

影响：即时推送、补查、周期、手动生成及恢复任务都检查白名单；私聊和范围外群聊入口丢弃，不缓存、不入池、不调用模型、不记录原文。保留群列表元数据用于添加群聊，既有完成的历史摘要与日志不自动删除。

0.5.0 的实现与验证见 [REST 与全流程白名单验收](../docs/REST与全流程白名单验收.md)。

## D05：Alpha 全部使用直接 HTTP

**状态：生效，覆盖旧 MCP 接入。** 用户明确要求应用直接调用 REST。账号、会话和消息改用 `/api/v1`，实时推送使用 HTTP SSE，应用不再调用 MCP。

影响：REST 参数与响应按真实接口适配，旧 MCP 补查游标做一次性迁移；不能仅改 URL 后沿用旧字段。改用 REST 不等于自动修复 Alpha 的数据状态问题。

## D06：CPA 摘要，Jev / 本地决策可选

**状态：生效。** 摘要统一使用 CPA 的 OpenAI 风格接口，模型能力通过 Codex 风格 `model_catalog_url` 获取。Jev 属于 TypeSafe，用户当前使用 OpenRouter，Base URL 必须支持自定义。

影响：决策与摘要分别配置，保留独立密钥、协议及模型设置；本地全员提及识别不能因为启用 Jev 而丢失。协议细节见 [接口与模型](03-接口与模型.md)。

## D07：已阅仅影响群岛

**状态：生效。** 用户明确选择“仅标记摘要已阅”，不把微信群标为已读。

影响：群摘要和需要关注都有一键已阅，支持逐条与本群操作；本地已阅、Alpha 未读、摘要成功标记分开保存。包含历史不使已阅记录重新亮点；「微信 N」不能被本地已阅操作清零。

## D08：统一摘要卡片与原文弹窗

**状态：生效，覆盖早期摘要 / 聊天切换设计。** 后续要求为群聊摘要与需要关注右侧形式一致，默认显示摘要，点击弹出聊天记录，支持已阅。

影响：复用左右双栏、阅读卡片和原文组件；添加群聊打开即可选择，不要求先搜索；监听页改表格；刘海宽度可配置。相关组件见 [界面与交互](04-界面与交互.md)。

## D09：日志落盘并实时可读

**状态：生效。** 日志不能只在内存，需留档，并覆盖本地决策、Jev 和摘要模型的入参出参。UI 支持即时刷新、跟随、分页、归档与稳定详情。

影响：诊断日志明确提示包含原文，排除密钥和鉴权头；不能因日志量大改成只保留屏幕当前内容。日志协议见 [数据日志与隐私](05-数据日志与隐私.md)。

## D10：最近一次 Alpha 未读问题停止排查

**状态：已停止，不是群岛待实施修复。日期：2026-10-22。** 用户最终确认：“没事了，就是 alpha 的问题，你不管了。”

此次后续排查没有修改群岛代码。用户的归因与停止要求记录在这里，不把尚未实施的排查设想写成已修复功能，也不宣称已从技术上验证所有上游原因。

影响：后续任务不要自动重启此排查、修改 Alpha 或新增未经确认的未读策略。若用户再次提出新的同步问题，应从新证据开始；其他独立改动仍保留已有未读同步功能。

## 后续维护

新增决定写明状态、覆盖对象、行为影响与代码 / 测试入口。未验收的动画、长时间运行、真实模型准确率等放到 [已知限制](08-已知限制与排查.md)，不要仅凭设计存在就标成已完成。用户没有重新要求的历史争议不自动变成待办。
