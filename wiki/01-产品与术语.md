# 产品与术语

[返回 Wiki 首页](README.md)

## 产品目标

用户的目标是辅助办公：微信群太多，无法逐一阅读，希望及时知道有人找自己、哪些讨论涉及自己的职责，以及有哪些需要跟进的事项。功能由即时相关性判断和周期摘要共同支撑。

应用形态为原生 macOS 主窗口、菜单栏图标及刘海面板。设计方向参考 Vibe Island；最初先用 HTML 确认高保真原型，再进入 Swift 开发。原型见 [prototype/index.html](../prototype/index.html)。

群岛当前是阅读和提醒助手，没有微信消息发送、自动回复或微信已读写入功能。

## 核心术语

| 术语 | 定义与边界 | 代码入口 |
| --- | --- | --- |
| 账号 | Alpha 提供的微信账号；与账号内的用户身份 `subjectID` 区分 | `Account` |
| 群聊范围 | 账号与群标识组成的独立处理范围 | `ConversationScope` |
| 白名单 | 用户显式选择的群集合；约束即时和周期等所有消息处理 | `Preferences.selectedGroups`、`MessageAdmission` |
| 实时缓冲 | 接收通过入口校验的消息，等待容量或固定时限后批量判断 | `RealtimeBuffer` |
| 相关性 | 消息或摘要与用户称呼、职责、关注事项相关；不必然意味着必须回复 | `RuleMatch`、`JevDecision`、`AIResult.relevant` |
| 需要回应 | 相关内容中的一类行动判断，内部保留，UI 不单独分成另一工作入口 | `needsResponse`、`Attention` |
| 微信未读 | Alpha 会话的 `unread_count`；群岛只读同步 | `ChatGroup.unread` |
| 完整未读快照 | 摘要执行时固定的群全部未读消息，包含仍未读的旧摘要消息 | `UnreadSnapshot` |
| 成功摘要标记 | 本次完整快照全部处理并持久化成功后的首末消息、数量及完成时间 | `SummaryMarker` |
| 摘要 | 模型生成的内容及其原文证据；可以相关，也可以无关 | `Digest` |
| 需要关注 | 直接提醒与相关摘要合并的用户阅读入口 | `AttentionFeed` |
| 摘要已阅 | 用户已在群岛阅读该摘要，独立于微信已读与模型成功进度 | `Digest.attentionReadAt` |
| 稍后提醒 | 关注记录延迟提醒，当前为 15 分钟；历史可见但到期前不算待关注 | `Attention.status`、`remindAt` |
| 补查进度 | 消息获取的位置，用于断线或分页恢复，不代表已摘要 | `Checkpoint` |

模型定义见 [Models.swift](../Sources/QundaoCore/Models.swift)，关注流见 [AttentionFeed.swift](../Sources/QundaoCore/AttentionFeed.swift)。

## 三种进度不能混用

| 进度 | 谁推进 | 推进条件 | 不代表什么 |
| --- | --- | --- | --- |
| 消息同步进度 | Alpha 消息读取流程 | 成功读取并保存相应页 | 不代表模型已处理 |
| 摘要成功进度 | 统一摘要任务池 | 全快照模型结果有效且原子保存成功 | 不代表微信已读或用户已阅 |
| 群岛本地已阅 | 用户的已阅操作 | 逐条、本群或一键已阅保存成功 | 不改变微信未读 |

例如，某群 100 条微信未读已成功摘要，用户在群岛点了已阅：摘要成功标记仍为 M100，摘要本地已阅，而微信未读数仍由 Alpha 决定。

## 白名单的边界

群列表元数据可用于添加群聊和显示未读状态；这不等于可以读取所有群的聊天正文。只有当前账号的显式白名单群能够进入消息缓存、模型及原文日志。

当前选择账号切换时会清空白名单，需要重新选择该账号的群；已有各账号的摘要和成功标记按账号隔离保存。不能因为两个账号出现相同群标识或消息 ID 就合并进度。

旧版“即时限白名单、周期扫描所有群”已经失效，详见 [决策记录](07-决策记录.md)。
