# 群岛

原生 macOS 微信群聊办公助手。使用 SwiftUI 主窗口、菜单栏和 AppKit 刘海面板，消息来自本机 Alpha，摘要统一使用 CPA 的 OpenAI Responses 接口，相关性判断可使用本地规则或 Jev。

## 项目知识库

- [AGENTS.md](AGENTS.md)：后续开发代理的协作方式、产品约束、隐私边界与验证要求。
- [群岛 Wiki](wiki/README.md)：已确认的产品规则、架构流程、接口、UI、数据日志、开发验收、决策记录及排查索引。

知识库按聊天中的最终确认整理；其中“即时和周期均限白名单”“完整未读作为摘要输入”“已阅仅影响群岛”覆盖早期不同方案。2026-10-22 最近一次未读同步排查已由用户确认属 Alpha 并要求停止，群岛未因此修改代码，见 [决策记录](wiki/07-决策记录.md)。

## 使用

1. 从 `/Applications/群岛.app` 打开应用，在「连接与模型」中填写 Alpha 令牌并连接。
2. 填写 CPA API Key，或点击「从 Codex 导入 CPA 密钥」，再点击「保存并获取模型」。密钥保存在 macOS 钥匙串中。
3. 在「关键词与规则」填写姓名、群昵称、负责事项等。在「监听群聊」点击「添加群聊」，直接勾选加入白名单（可搜索筛选）后开始监听。
4. 需要系统通知时，在「刘海与通知」主动开启授权。

## 界面与交互

- 监听页改为白名单表格：默认不自动加入群，支持搜索、排序、多选移出；添加窗口直接显示全部可添加群，支持搜索筛选、全选当前列表和清空选择。旧版监听范围备份在 `previousSelectedGroups`，升级后需要重新明确选择白名单。
- 「群聊摘要」与「需要关注」复用左右双栏：左侧按群选择，右侧独立滚动阅读。
- 「需要关注」集中显示所有相关内容，不再按找我或相关摘要分类。主窗口、刘海和菜单栏使用同一待关注计数；已阅内容可在「包含历史」中回看。
- 「需要关注」和刘海的群列表小点只表示该群待阅的关注记录数量；「包含历史」不会让已阅或稍后提醒重新亮点。「群聊摘要」中的微信未读数仍以 Alpha 为准，并明确标注「微信」。摘要批数、关注记录数和微信未读数分别展示；群岛中已阅摘要或处理提醒不会修改微信已读状态。
- 未读状态独立刷新，每次读取完成后等待 5 秒；暂停监听仍更新，打开窗口、回到前台、系统唤醒时立即刷新。同步失败保留上次状态，界面提供同步时间和手动刷新入口。
- 「群聊摘要」和「需要关注」共用右侧摘要卡片，点击「查看原文」弹出本批聊天记录。均支持逐条已阅和「一键已阅」，群聊摘要还可将本群摘要全部标为已阅。只更新群岛本地状态，不修改微信未读，也不提前标记操作后新到的摘要。
- 摘要列表按 Alpha 最新未读消息时间倒排，有未读的群优先；没有未读时按摘要中的最新消息时间排序，旧记录无原文时才回退到生成时间。卡片内部也按消息时间倒排。「生成未读摘要」用于主动扫描当前账号的白名单群，只有未读范围变化才生成摘要。
- 聊天仅显示已同步或随摘要保存的文字原文，图片等当前显示来源的文字占位，不包含发送入口。
- 称呼与关键词按实际宽度紧凑换行。
- 「刘海与通知」可分别调整收起、展开宽度。默认收起宽度比原版更窄，并避开摄像头；尺寸变化使用窗口动画，内容随后淡入，尊重系统减少动态效果设置。

## 0.4 统一摘要流程

- 直接命中配置的 `@称呼`、点名请求、`@所有人` / `@all` / `@everyone` / `@全体成员` 等群体提醒或结构化提及时，立即显示群名、发送人和原文。纯文本命中会在理由中标明，不能等同于微信原生提及身份认证。
- 关键词与系统本地中文语义嵌入仅筛选候选，随后由 AI 结合上下文确认。系统语义模型不可用时，界面会说明，继续进行关键词和周期分析。
- 实时消息按账号、群聊去重后进入持久化缓冲池。默认累计 30 条或首条消息等待 3 秒后批量判断，持续来消息不会延后截止时间。无关消息不触发即时摘要；同批同群命中多条也只提交一个任务。白名单同时约束即时监听、补查、周期摘要和手动生成；私聊及白名单外群聊在入口丢弃，不缓存、不入池、不调用模型、不记录原文。
- 周期任务按独立时钟扫描所选账号的白名单群。没有未读直接跳过；当前末条未读与该群上次成功摘要末条一致时不调用摘要模型。开始监听后从完整周期计时，可选择 5 / 15 / 30 分钟或手动生成未读摘要。
- 两种触发共用一个任务池：按账号和群合并，同群串行，不同群默认并发 3（设置支持 1–8）。即时任务优先于等待中的周期任务，不打断已运行请求。运行中的新触发合并成一次后续检查；只有相关判断命中或周期扫描才会产生新触发。
- 执行时从 Alpha 完整分页读取当时全部未读，固定快照后再调用模型。已摘要但仍未读的旧消息继续参与上下文。例如 M1–M100 成功后标记 M100；后来出现 M101 且满足触发条件时，若之前仍未读，就摘要全部 101 条。
- 超过所选模型预算时完整分段整理、再逐级汇总；单条长消息也按字符完整拆分。所有分段和最终结果都有效后，才将摘要、原文快照、末条成功标记和任务状态原子写入同一文件。失败、取消、输出无效、分段未完成或保存失败均不推进标记。
- 任务失败从 10 秒开始退避，最多 5 分钟。等待、重试和运行中任务、实时缓冲及 Jev 待判断批次均可恢复。旧版 `analyzed` 或部分摘要不冒充完整未读成功记录；升级后必要时会首次重新整理完整未读。
- 刘海直接打开统一的「需要关注」，左侧选群，右侧阅读摘要和打开原文。已阅内容从待关注中移除，无关摘要不进入刘海。
- Alpha SSE 不支持重放。应用以服务器消息 ID 去重，30 秒补查、重连补查与睡眠唤醒恢复提供补充。失败不会推进当前分页进度。
- 「已处理」不修改微信已读；「稍后」持久保存 15 分钟提醒时间。应用暂停/退出时不会发通知，恢复运行后检查到期提醒。

## Jev 决策模型

在「关键词与规则」选择「本地识别」或「Jev 决策模型」。本地方式以称呼、关键词和系统语义筛选候选；CPA 摘要再结合上下文判断回应需求。

在「连接与模型」可自定义 Base URL、接口协议、模型名称和独立密钥，也可填入预设：

| 服务 | Base URL | 协议 | 默认模型 |
| --- | --- | --- | --- |
| OpenRouter | `https://openrouter.ai/api` | Decisions API | `~typesafe/jev-latest` |
| TypeSafe | `https://api.typesafe.ai/v1` | System One API | `jev-latest` |

OpenRouter 常见的 `/api/v1` 地址也会按所选协议正确解析；支持完整接口地址和自定义代理路径，界面显示最终请求地址。地址、协议、模型与密钥只在点击保存后一起生效，编辑草稿不会影响正在运行的连接。旧版 TypeSafe 连接保留原服务。

协议依据：[OpenRouter Jev 官方文档](https://openrouter.ai/docs/guides/community/jev)、[Decisions API](https://openrouter.ai/docs/api/api-reference/alphadecisions/submit-a-decisions-request)、[TypeSafe System One](https://docs.typesafe.ai/api/system-one)。
- 每条消息有两个 `noul` 问题：与我相关的概率、需要我回应的概率，默认阈值 75%，界面可调整。
- 白名单消息经容量/固定时限 flush 后按群交给 Jev；单次请求最多 20 条，长批次完整分段判断，全部完成后同群只触发一次。判断队列独立于 CPA 摘要任务池。
- 明确 @我 和群体提醒始终由本地优先处理。Jev 命中后为该群安排完整未读摘要；消息缓存、周期摘要均仅限白名单群未读。
- 断线时保留待决策集合，退避重试，同时回退本地筛选；概率缺失、非数值或越界均不能视为成功决策。
- Jev 的不确定判断会注明来源与概率，不等同于确定有人找你。聊天正文属于不可信待分析数据，不是模型指令。

Jev 的 OpenRouter 与 TypeSafe 协议已完成模拟 HTTP 验证；本轮未重新验收真实 Jev 判断。填写对应服务密钥后，可以在应用中用合成消息测试连接；请求与结果可在日志页查看。
## CPA 模型目录

固定地址：`https://cpa.bgp.kiliter.cn/v1/models`。采用 Codex `model_catalog_url` 的请求方式，添加 `client_version=0.134.0` 并复用 CPA Bearer 鉴权。该参数用于目录协议兼容，不宣称本应用是 Codex。

实际验证：不带参数返回普通 `data` 模型 ID 列表；带参数返回 `models` 原生目录，包含 `slug`、`display_name`、`context_window`、`max_context_window`、`max_tokens`、`supported_reasoning_levels` 等字段。

应用使用 Responses `/v1/responses`，不包含工具调用，设置 `store:false`。按目录预算完整分段并汇总，并验证 AI 输出的消息引用。目录中的编码代理指令不会作为聊天分析提示使用。

参考实现：[Codex 模型目录客户端](https://github.com/openai/codex/blob/main/codex-rs/codex-api/src/endpoint/models.rs)。

## 数据与日志

- Alpha 账号、会话、消息均通过 `/api/v1` REST 接口读取，实时推送使用同一路径下的 HTTP SSE；不调用 MCP。CPA 与 Jev 继续直接使用各自的 HTTP API，OpenRouter 自定义配置保留。
- 状态：`~/Library/Application Support/Qundao/state.json`，原子写入，包含进度、去重标识、未处理消息、提醒和摘要。目录权限 700，文件权限 600。
- 日志：`~/Library/Application Support/Qundao/Logs/群岛-日期.jsonl`。按日写入并同步磁盘，单文件超过 10 MB 滚动归档，历史不自动删除。界面显示文件尾部，完整日志始终保留在磁盘。
- 运行事件记录连接、队列、摘要耗时和错误，群与消息使用脱敏引用。新增诊断日志在 `Logs/Diagnostics/诊断-日期-序号.jsonl`，记录本地决策、Jev 和 CPA 的入参、出参、错误、HTTP 状态、耗时及关联编号。**诊断日志包含聊天正文和配置的称呼、关键词**，用于排查判断依据；不传入鉴权头，已知密钥及返回中的密钥字段会脱敏。
- 日志页支持来源筛选、入参 / 出参 / 错误切换、复制、25 / 50 / 100 条分页和打开归档。默认「实时刷新」和「跟随最新」：日志成功落盘后立即通知界面，批量事件合并刷新，不必等定时轮询。选择记录或滚动时只暂停跟随，最新页仍刷新并保留正在看的详情；查看历史分页时显示新日志提示，点击即可回到最新。读取在后台进行，分页位置不受追加或归档影响。
- 密钥：macOS 钥匙串，服务名 `cn.kiliter.qundao`。
- 消息缓存、待办和成功标记保存在本地；摘要保留最近 500 个完整快照，成功标记不随摘要展示数量裁剪。没有自动清空微信数据或自动回复功能。

## 开发

```bash
swift test
./script/build_and_run.sh --build-only
./script/build_and_run.sh --verify
```

脚本固定复用本机已有开发签名身份，构建 `.app` 后安装至 `/Applications` 启动。不自动创建证书、不修改系统信任、不使用每次变化的临时签名。

更换开发机器时，通过 `QUNDAO_SIGNING_IDENTITY` 指定该机器的固定代码签名证书指纹；不应把私钥写入仓库。

真实集成测试默认跳过；需由调用环境注入 `QUNDAO_TEST_CPA_KEY` 和 `QUNDAO_TEST_ALPHA_TOKEN`，CPA 测试仅发送合成消息。Alpha 完整未读分页测试还需通过 `QUNDAO_TEST_ALPHA_GROUPS` 传入逗号分隔的白名单群标识，仅选择其中适合验证的群。密钥不要写入脚本或提交。

## 验证边界

0.5.0 已改用 Alpha REST，并将白名单统一应用于即时推送、补查、周期摘要、手动生成和任务恢复。103 项测试中 100 项通过、3 项真实接口测试默认跳过；另外启用的 2 项 Alpha REST 只读测试通过。安装版已验证推送连接和白名单范围内的持久化状态，并观察到一条真实消息经缓冲后由 Jev 成功判断为未达阈值、未触发即时摘要。本轮未重新验收 CPA 输出及 Jev 判断准确率，详见 [REST 与全流程白名单验收](docs/REST与全流程白名单验收.md)。升级会清理当前账号白名单外的处理缓存与待办；既有历史摘要和日志保留。

0.4.3 修复历史关注小点：90 项测试中 87 项通过、3 项真实接口测试默认跳过。安装版已确认 6 个已阅历史群均无小点，摘要页仍正确保留并标注微信未读。详见 [历史关注小点修复验收](docs/历史关注小点修复验收.md)。

0.4.2 统一阅读、消息时间排序与日志即时刷新：85 项测试中 82 项通过、3 项真实接口测试默认跳过。安装版已验证原文弹窗、新日志自动入列及保持已选详情，详见 [统一阅读与即时日志验收](docs/统一阅读与即时日志验收.md)。

0.4.1 已完成关注记录和未读状态修复回归：77 项测试中 74 项通过、3 项真实接口测试默认跳过。安装版与真实 Alpha 的 63 个群未读计数全部一致；微信到 Alpha 的实际已读同步延迟未测量。详见 [关注与未读同步验收](docs/关注与未读同步验收.md)。下述摘要模型的真实运行结果来自 0.4.0 验收。

0.5.0 已验证真实 Alpha REST 的账号/群读取，以及每页 2 条的完整未读快照只读分页。接口提供 `unread_count`、末条消息查询和 offset 分页，但没有原子未读快照或独立已读边界。当前按最新 N 条构造未读，并在分页前后复核未读数量及末条；边界变化最多重取 3 次，无法确认完整性则保留任务重试。无法凭这些接口承诺数据库级原子快照；大量持续流量、边读边收消息及 Alpha 未读计数同步延迟仍需真实使用验收。改用 REST 不代表微信到 Alpha 的已读同步问题已解决。

CPA、Jev 的请求与错误路径有模拟 HTTP 验证。0.4.0 安装版按当时的全群规则真实扫描 63 个群，对 7 个未读群的 97 条消息完成 CPA 摘要并落盘成功标记；再次扫描相同未读范围没有新增模型请求。该历史结果不代表 0.5.0 仍扫描白名单外群聊。Jev 真实判断、长文本分层汇总的内容质量、长时间运行和跨休眠行为仍需进一步验收。历史自动化测试与真实模型结果见 [摘要流程验收](docs/摘要流程验收.md)。
